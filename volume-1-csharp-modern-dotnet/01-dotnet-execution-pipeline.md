# The .NET Execution Pipeline

## Overview

Understanding how a .NET application executes is one of the most common topics in senior .NET interviews. A good engineer doesn't just know how to write C# code—they understand what happens underneath the runtime.

This chapter covers the complete execution pipeline, from writing C# code to executing native machine instructions on the CPU.

---

# 1. What happens when you run a .NET application?

## Interview Answer

When a .NET application starts, the C# code has already been compiled into Intermediate Language (IL) by the Roslyn compiler. The Common Language Runtime (CLR) loads the application assembly, verifies metadata, resolves dependencies and prepares the runtime environment.

Methods are not compiled immediately. Instead, the Just-In-Time (JIT) compiler translates each method into native machine code the first time it is executed. The generated native code is cached and reused for subsequent calls.

During execution, the CLR also manages memory, thread scheduling, exception handling, security checks and garbage collection.

### Execution Pipeline

```text
C# Source Code
        │
        ▼
Roslyn Compiler
        │
        ▼
Intermediate Language (IL)
        │
        ▼
Assembly (.dll/.exe)
        │
        ▼
CLR Loads Assembly
        │
        ▼
JIT Compilation
        │
        ▼
Native Machine Code
        │
        ▼
CPU Execution
```

### Key Points

- Roslyn compiles C# into IL.
- IL is platform-independent.
- CLR is responsible for executing managed code.
- JIT compiles methods on first execution.
- Native code is cached after compilation.

### Common Follow-up Questions

- Why does .NET use IL?
- Does JIT compile the whole application?
- Can IL be decompiled?

---

# 2. What is the CLR?

## Interview Answer

The Common Language Runtime (CLR) is the execution engine of .NET. It provides all runtime services required to execute managed code.

Its responsibilities include:

- Loading assemblies
- JIT compilation
- Garbage Collection
- Exception handling
- Thread management
- Memory management
- Type safety
- Security verification

Think of the CLR as the operating system for managed .NET applications.

### Senior Tip

Many candidates incorrectly say that the CLR compiles C# code.

That is incorrect.

Roslyn compiles C# into IL.

The CLR executes IL.

---

# 3. What is Intermediate Language (IL)?

## Interview Answer

Intermediate Language (IL), sometimes called CIL or MSIL, is a CPU-independent instruction set generated by the C# compiler.

Instead of producing x64 or ARM instructions directly, the compiler produces IL. This allows the same assembly to execute on multiple platforms.

### Example

C#

```csharp
public int Add(int a, int b)
{
    return a + b;
}
```

Equivalent IL (simplified)

```text
ldarg.1
ldarg.2
add
ret
```

### Why IL?

- Platform independence
- Runtime optimizations
- Cross-platform compatibility
- Better security verification

---

# 4. What is JIT Compilation?

## Interview Answer

The Just-In-Time (JIT) compiler converts IL into native machine code when a method executes for the first time.

Only executed methods are compiled.

Once compiled, native code is cached and reused.

### Benefits

- CPU-specific optimizations
- Faster startup than compiling everything
- Runtime optimizations based on execution environment

### Common Misconception

The entire application is **not** JIT compiled at startup.

Only methods that are actually executed.

---

# 5. ReadyToRun vs JIT vs Native AOT

| Feature | JIT | ReadyToRun | Native AOT |
|---------|-----|------------|------------|
| Startup | Medium | Fast | Fastest |
| Runtime Compilation | Yes | Partial | No |
| Output | IL | IL + Native | Native |
| Reflection Support | Full | Full | Limited |

### Interview Tip

Unless startup time is critical, standard JIT compilation is still the most common choice because it provides excellent compatibility and runtime optimizations.

---

## Summary

- Roslyn compiles C# into IL.
- CLR executes managed code.
- JIT converts IL into native instructions.
- Native code is cached after first execution.
- ReadyToRun improves startup.
- Native AOT removes the need for JIT.
